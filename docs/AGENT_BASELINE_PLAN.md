# KernelAgent 基线资格与正式比较题单

本工作线先用上游 KernelAgent 的单 worker `greedy` 校验本地四阶段 `single` 的能力，再用同一裁判比较通用提示和四个专门角色。两条搜索入口都交付定义 `kernel_function` 的完整 Triton 模块。共享起点、题目、验证输入、候选预算和计时规则使每个结果能追溯到实际评测的源码。

## 已完成的资格检查

| 四候选开发搜索 | 正确候选 | 确认提速候选 | 每次搜索费用 |
| --- | ---: | ---: | ---: |
| `single`（6 次） | 23/24 | 10/24 | 0.263–0.506 美元 |
| `greedy`（4 次） | 5/16 | 1/16 | 0.088–0.120 美元 |

matvec 原先在同卡直接配对得到 `single` / `greedy` 为 3.56 / 10.73 ms 和 3.23 / 8.47 ms。调整阶段输出后，`single` 在同两个开发种子上的终选为 6.73 ms 和 4.69 ms，这次只复跑了 `single`。随机抽四组启动参数的中位数为 4.10 ms。softmax 和 LayerNorm 各一个开发种子，两边均保留起点。这些结果支持将 `single` 用作正式角色比较的基线。两道归约题的正式结果需同时报告产出确认提速的搜索次数和终选延迟。

在 matvec 的一个开发种子上，`multi` 的 4 个真实候选全数通过正确性检查，第一、第四稿确认提速。终选是两次启动的分块归约，配对用时 3.906 ms，原起点 10.776 ms。16 次请求使用 164,763 个输入 token、11,116 个输出 token，合计 0.418454 美元。四个阶段的全部回复符合约定。这次冒烟独立于正式比较。

截至该冒烟，项目累计用量为 17.0311236 美元，总额 100 美元，供新 campaign 使用的余额为 82.9688764 美元。正式搜索在合并后按主线提交、题单、新种子和知识卡选择登记，使用每次四个候选、最多 16 次调用的预算。[公共题协议](PROTOCOL.md)

## 正式比较的题单与选题依据

正式角色对照保留 matvec（第 4 题）、softmax（第 23 题）、LayerNorm（第 40 题）和 FP32 矩阵乘（第 2 题），四题均使用原始冻结起点。每题用相同的五个新种子配对比较 `single` 与 `multi`，无知识卡的主比较共 20 对、40 次搜索。下述扫描量化了矩阵乘单靠调参可得到的加速。

矩阵乘使用公开的 FP32 形状 `(2048, 8192) @ (8192, 4096)`，保持 IEEE 精度。原起点在预检中为 11.001 ms，eager 为 8.332 ms，`torch.compile` 为 8.818 ms。以起点对自身做两组各 20 次校准，两组在 1.01 阈值下都没有误判。只改分块、warp 数和流水级数，72 组配置全部数值正确，62 组在筛选中确认提速；最快的 8 组都通过三次独立终验。随机抽四组取最好时的中位数为 9.064 ms。

最优配置为 BM=64、BN=64、BK=32、4 个 warp、3 级流水。下表每行的两个延迟都来自该行配对，表中延迟与比值分别对三次终验取中位数。

| 配对对象 | 调优内核（ms） | 对照（ms） | 调优内核相对对照的延迟 |
| --- | ---: | ---: | ---: |
| 原起点 | 8.704 | 11.140 | 快 22.2%，加速 1.286 倍 |
| PyTorch eager | 8.431 | 8.276 | 慢 1.3% |
| `torch.compile` | 8.223 | 8.668 | 快 5.5% |
